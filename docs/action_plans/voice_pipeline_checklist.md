# Voice Pipeline Checklist - Deepgram, Grok, and Google TTS

## Goal
Realign Rex around the voice pipeline needed for real street/pocket use:

```text
iPhone microphone
-> Flutter streams microphone frames continuously
-> FastAPI WebSocket voice session
-> Deepgram live streaming transcription
-> FastAPI emits partial/final transcript events
-> Final transcript enters PromptService + ChatService
-> Grok streams assistant tokens
-> Backend chunks tokens into speakable phrases/sentences
-> Google Text-to-Speech generates audio chunks
-> FastAPI streams audio events back to Flutter
-> Flutter plays audio chunks while the session stays open
-> Supabase stores messages, memory candidates, and voice metadata
```

## Why This Exists
Action Plans 1-7 did not originally contain a complete Deepgram + Google TTS implementation plan, and the first implemented cloud path still uses upload-per-turn voice calls.

- Action Plan 1 covers time-aware prompt foundation for Grok.
- Action Plan 2 implemented a local foreground voice MVP using Flutter `speech_to_text` and `flutter_tts`.
- Action Plan 5 covers background and locked-screen continuation, but it assumes the current local voice services and does not define Deepgram or Google TTS.
- No action plan currently creates Deepgram backend services, Google TTS backend services, voice API routes, cloud audio streaming, credential handling, or cloud voice integration tests.

Local STT/TTS is useful for early UI testing, and upload-per-turn cloud voice is useful as a fallback. Neither is the final target for Rex as a street/pocket daily driver. The target pipeline should stream microphone audio, live transcripts, Grok tokens, and TTS audio chunks through backend-owned cloud services while keeping secrets on the backend.

## Architecture Decision

### Required Production Direction

```text
User speaks into phone
-> Flutter streams audio frames to FastAPI
-> FastAPI receives a persistent voice WebSocket session
-> Deepgram transcribes speech live and returns interim/final transcripts
-> Rex sends final transcripts into existing ChatService
-> PromptService injects time, memory, personality, and context
-> Grok streams response tokens
-> Backend converts speakable chunks into Google TTS audio
-> Flutter plays streamed audio chunks
-> Supabase stores conversation, messages, and useful voice metadata
```

### Security Rules
- Do not ship Deepgram API keys in Flutter.
- Do not ship Google service account credentials in Flutter.
- FastAPI owns all vendor secrets.
- Flutter may receive only short-lived tokens, temporary URLs, or raw audio bytes generated by FastAPI.
- Grok, Supabase, Deepgram, and Google credentials stay in `.env` on the backend/VPS.

### Existing Fallback Paths
Keep the current local path as a fallback/dev path only:

```text
speech_to_text -> Grok -> flutter_tts
```

Keep the current upload-per-turn cloud path as a reliable fallback:

```text
record utterance -> POST /voice/turn -> Deepgram -> Grok -> Google TTS -> play finished audio
```

Neither fallback should be treated as the final street/pocket architecture.
