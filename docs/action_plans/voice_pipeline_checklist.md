# Voice Pipeline Checklist - Deepgram, Grok, and Google TTS

## Goal
Realign Rex around the voice pipeline needed for real street/pocket use:

```text
Flutter audio capture
-> FastAPI voice route
-> Deepgram speech-to-text
-> FastAPI chat orchestration
-> Grok
-> Google Text-to-Speech
-> Flutter audio playback
-> Supabase voice/conversation metadata
```

## Why This Exists
Action Plans 1-7 do not currently contain a complete Deepgram + Google TTS implementation plan.

- Action Plan 1 covers time-aware prompt foundation for Grok.
- Action Plan 2 implemented a local foreground voice MVP using Flutter `speech_to_text` and `flutter_tts`.
- Action Plan 5 covers background and locked-screen continuation, but it assumes the current local voice services and does not define Deepgram or Google TTS.
- No action plan currently creates Deepgram backend services, Google TTS backend services, voice API routes, cloud audio streaming, credential handling, or cloud voice integration tests.

Local STT/TTS is useful for early UI testing, but it is not the target for Rex as a street/pocket daily driver. The target pipeline should move speech recognition and speech synthesis into reliable cloud-backed services while keeping secrets on the backend.

## Architecture Decision

### Required Production Direction

```text
User speaks into phone
-> Flutter records audio
-> FastAPI receives audio stream or audio chunks
-> Deepgram transcribes speech
-> Rex sends transcript into existing ChatService
-> PromptService injects time, memory, personality, and context
-> Grok returns response text
-> Google TTS generates audio
-> Flutter plays response audio
-> Supabase stores conversation, messages, and useful voice metadata
```

### Security Rules
- Do not ship Deepgram API keys in Flutter.
- Do not ship Google service account credentials in Flutter.
- FastAPI owns all vendor secrets.
- Flutter may receive only short-lived tokens, temporary URLs, or raw audio bytes generated by FastAPI.
- Grok, Supabase, Deepgram, and Google credentials stay in `.env` on the backend/VPS.

### Existing Local Voice Path
Keep the current local path as a fallback/dev path only:

```text
speech_to_text -> Grok -> flutter_tts
```

It should not be treated as the final street/pocket architecture.
